# Schedule Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Schedule screen (Jobber's Schedule, PRD 3.5): Month, Week and Day calendars, bookings with double-booking prevention, availability, unscheduled panel, and the link to the pipeline.

**Architecture:** Backend in `convex/crm/schedule.ts` on a new `calendarEvents` table (consultations, follow-up visits, events, reminders) plus optional start and end on existing tasks. Pure rules (overlap, working hours, repeat expansion) live in `convex/crm/lib/schedule.ts`. `schedule.range` returns the expanded items for a window. The UI is `/schedule` with its own CSS, built like the pipeline: skeleton, hover feedback, smooth motion, tooltips.

**Tech Stack:** Next.js 16 (read `node_modules/next/dist/docs/` first), React 19, Convex (read `convex/_generated/ai/guidelines.md` first), convex-test + vitest in `CRM/tests/`.

**Spec:** `CRM/docs/superpowers/specs/2026-11-10-schedule-design.md` (approved 2026-11-10; the external calendar is Zoho, not Google). Also read `CRM/CLAUDE.md`, the repo-root `CLAUDE.md`, and the pipeline files this builds on: `convex/crm/pipeline.ts` (`applyMove`), `convex/crm/opportunityTasks.ts`, `CRM/components/pipeline-*.tsx`, `CRM/app/pipeline.css`.

## Global Constraints

- Dev deployment only. Never `npx convex deploy` or any `--prod`.
- Schema edits additive and optional only; forms tables and `convex/projects|sales|jobber` untouched. New backend files in `convex/crm/`; file names use only letters, digits, underscores, periods.
- Every function starts with `requireBusiness` (read) or `requireEditor` (write). Admin, Sales, Office Team edit; Project Managers read only. An assignee must be an active user of the business (an Admin counts for all), checked by the same helper the tasks use.
- Money is not involved. Time zone `America/Los_Angeles` (`BUSINESS_TIME_ZONE` in `CRM/lib/format.ts`); queries never read the clock, callers pass `now`.
- Item types: `"consultation" | "visit" | "event" | "reminder"` in `calendarEvents`; tasks are a fifth kind shown from `opportunityTasks`. Statuses stored: `"upcoming" | "completed" | "confirmed"`; **Overdue is derived** (not completed and ended before `now`), never stored.
- Blocking items for double-booking: consultation, visit, event. Tasks and reminders never block. Two blocking items for the same person may not overlap (touching end to start is allowed). Outside working hours is allowed (the UI warns).
- Default working hours: Monday to Friday, 08:00 to 17:00. Stored per business in `scheduleSettings`.
- Booking a consultation for a project at "Schedule Onsite Consultation" moves it to "Onsite Consultation" through `applyMove` in `convex/crm/pipeline.ts` (reuse; do not patch `stage`).
- UI rules from `CRM/CLAUDE.md`: skeleton per screen; hover and press feedback on everything clickable; red invalid fields on submit; smooth 120 to 260 ms motion with exit animations; unbuilt controls are greyed `disabled`; tooltips via `data-tip`.
- Out of scope: the Zoho link (its own later step; leave one function `externalBusy` in the availability code that returns `[]`), the map (Map button greyed), Jobs and crews (greyed), anything that needs a client-facing link.
- No commits unless the user asks. Commit steps apply only then; messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- An item that crosses midnight and one that spans several days appear on each day they cover in Week and Month.
- A repeating item whose first date is before the window still appears inside it; one that starts after the window does not.
- Two bookings that touch (one ends 10:00, the next starts 10:00) are allowed; overlapping by one minute is refused.
- Moving an item onto itself (same person, overlapping its own old time) is not a conflict.
- Daylight saving: a daily repeat at 10:30 stays at 10:30 local on the days the clocks change.
- A consultation booked for a project not at "Schedule Onsite Consultation" does not move the project.
- A user removed from the business keeps their past items but cannot be assigned new ones.
- Cancel and Escape on every pop-up leave the calendar unchanged.
