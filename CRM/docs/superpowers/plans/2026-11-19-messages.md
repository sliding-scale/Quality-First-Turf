# Messages (texts): communication log, inbox and a sender ready for Twilio (PRD 5.3, Jobber's Message Center)

> Built in the session (the user chose to build here). Backend rules get a failing test first.

**Goal:** Launchpad has Messages: every text to or from a client is logged against the client (and the job, when it came from one) and the user who sent it; staff read and send them from a Messages page and a top-bar Message Center. Sending works by hand today (the phone's messaging app) and goes through Twilio the moment the keys and a number are set.

**Read first:** Jobber's top-bar **Message Center** (a drawer; Jobber's own shows its registration notice while texting is being approved). PRD 5.3: multiple business numbers, send and receive texts, logs against customers and opportunities, activity tied to the user. Calls (5.3) and WhatsApp (5.4, with the installer work packages of 4.3) are a later plan.

## My calls (D-091)
- **Provider:** Twilio (Q-006 assumed it). One log whatever the provider, so a change later touches only the sender and the webhook.
- **Numbers:** a `phoneNumbers` table per business (Settings > Phone numbers, Admin); an inbound text is filed under the business that owns the number it was sent to; a send uses that business's first number.
- **Until the keys and a number exist:** Send writes the message as "sent by hand", and the screen opens the phone's messaging app with the text filled in (the workaround from D-094). Nothing is sent from the CRM.
- **Inbound:** an HTTP route `/twilio/sms` checks Twilio's signature, matches the sender to a client by the last ten digits of their phone numbers (else keeps it under the bare number), and logs it unread.
- **Conversations** are by client (or by bare number when no client matches); Jobber's thread layout.
