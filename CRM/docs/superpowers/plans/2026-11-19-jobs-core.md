# Jobs (core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Closed Won project is a job: a Jobber-style Jobs list and job page, Close Job, Convert to Job, and New Job by hand, all on the dev deployment.

**Architecture:** A job is an `opportunities` row with `outcome: "won"` seen through new screens, not a new record. Job number, status and totals are computed or written in one place each. Backend is additive in `convex/crm/jobs.ts` plus small additive schema fields.

**Tech Stack:** Convex (`convex/crm/`), Next.js 16 App Router (`CRM/`), plain CSS in `CRM/app/globals.css`, vitest + convex-test (`CRM/tests/`).

**Spec:** `CRM/docs/superpowers/specs/2026-11-19-jobs-design.md` (approved by the user 2026-11-19). This plan covers spec steps 1 to 4. Steps 5 (catalogue), 6 (Labor, Expenses), 7 (Checklists, recurring jobs, emails, signature, costs CSV, texts) each get their own plan later, because each ships and tests on its own.

## Global Constraints

- Work on the **dev deployment only**. Never `npx convex deploy` or `--prod` (root CLAUDE.md rule 2). Do not commit unless asked.
- **Additive only:** no edits to the forms tables or `convex/projects`, `convex/sales`, `convex/jobber`. Schema edits add optional fields or new tables.
- Convex file names: letters, digits, underscores, periods only. Read `convex/_generated/ai/guidelines.md` before writing Convex code.
- Every CRM function starts with `requireModule(ctx, businessId, "jobs", level)` or `requireProject(ctx, project, "jobs", level)` (`convex/crm/lib/access.ts`). Never a role check.
- Every new screen: skeleton in `CRM/components/skeletons.tsx` plus a `loading.tsx` (D-034); hover and press feedback and pointer cursor on everything clickable (D-035); `<table class="table">` with a `<colgroup>` (D-035); red invalid fields on submit (D-035); 120 to 260 ms motion with exit animations (D-037); tooltips via `data-tip`; checked at 400 px wide.
- Statuses and totals are computed from records, never typed or stored (CRM rule 7). Lists paginate.
- `convex/shared/` is not touched by this plan.
- Run tests from `CRM/`: `npx vitest run tests/<file>`. The 27 failures in `access.test.ts` and `invitations.test.ts` are older and unrelated.

## Review Focus

1. A project marked Closed Won twice (won, reopened, won again) keeps its first job number. Test in Task 3.
2. Two businesses both start at job number 1; one never sees the other's jobs. Test in Task 3 and Task 4.
3. A job whose quote has no lines or a hand-made job with no lines shows a $0.00 total, not an error. Test in Task 4.
4. An Installer (assigned-only) never sees the Jobs list; a Sales person can look but not Close Job or create one. Test in Task 1 and Task 6.
5. Convert to Job on an unsigned or un-deposited quote shows the existing Closed Won refusal, and creates no job number. Test in Task 8.

### Task 4: Jobs queries

**Files:**
- Modify: `convex/crm/jobs.ts`
- Test: `CRM/tests/jobs.test.ts`

**Interfaces:**
- Consumes: `jobStatusOf`, `JobFacts` (Task 2); `projectMoney`, `billingTotalOf` from `convex/crm/lib/billing.ts`; `calendarEvents.by_opportunity` rows of `type: "visit"`.
- Produces:
  - `type JobRow = { id: Id<"opportunities">; jobNumber: number; title: string; clientId: Id<"clients">; clientName: string; property: string; firstVisitAt: number | null; nextVisitAt: number | null; status: JobStatus; totalCents: number }`
  - `jobs.list` query, args `{ businessId, status?: string, search?: string, page: number, dayStart: number }`, returns `{ rows: JobRow[]; total: number; pageSize: 25 }`. Search matches `opportunities.searchText` (client name, code, title) case-insensitively. Rows sort by `jobNumber` descending.
  - `jobs.counts` query, args `{ businessId, dayStart }`, returns `{ all: number; byStatus: Record<JobStatus, number>; endingSoon: number; visitsPast30: { count: number; cents: number }; visitsNext30: { count: number; cents: number } }` (cents = summed job totals of jobs that have a visit in the window).
  - `jobs.get` query, args `{ id }`, returns the `JobRow` fields plus `{ projectCode, pipeline, stage, client: { name, phone, email }, lines: { name; description; quantity; unitPriceCents }[], subtotalCents, visits: ScheduleItem-like rows (id, start, end, anytime, status, title, notes, assigneeIds), closedAt: number | null, closedByName: string | null, quoteId: Id<"quotes"> | null }`.
  - Job total: `billingTotalOf(...)` when above 0, else the sum of the project's `lines`; 0 when neither.
  - Job property: the client's first property, formatted `street1, city, state zip`, else the client's street fields, else "".

- [ ] **Step 1: Write failing tests** with `seeded()`: a won project appears in `list` with its number, client name and total from the signed quote; a business never lists another's jobs (Review Focus 2); a project not won is absent; `status: "Late"` returns only jobs with an `upcoming` visit before `dayStart`; `search` narrows by client name; `page: 2` returns rows 26 onward with 30 jobs seeded directly through `base.run`; `counts.byStatus` adds up to `all`; a won project with no quote and no lines has `totalCents === 0` (Review Focus 3); an Installer's `list` call is refused with "You do not have access to this."; `get` returns lines, visits and the client.
- [ ] **Step 2: Run** `npx vitest run tests/jobs.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** the three queries. Read the business's won projects with the `by_business_and_jobNumber` index (`take(300)`; a comment notes this cap and says to revisit past it), derive each row's facts (visits from `calendarEvents.by_opportunity`, `inFinance` from `pipeline === "Finance"`, `invoicesCover` from `projectMoney(...).covered`), filter, sort and slice on the server. `requireModule(ctx, businessId, "jobs", "view")`; `get` uses `requireProject(ctx, project, "jobs", "view")`.
- [ ] **Step 4: Run.** Expected: PASS.
- [ ] **Step 5: Commit** `feat: jobs list, counts and get`.
