# Finance (invoices, payments, Finance pipeline) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build PRD 5.1 and 5.2 as designed in the spec: Jobber-style invoices and payments, a payment schedule on the project, and a six-stage Finance board that moves itself.

**Architecture:** New additive Convex tables and modules under `convex/crm/` (pure money rules in `lib/invoiceMath.ts`), one existing validator widened (`opportunities.pipeline`). The Finance board reuses the Preplanning/Construction board machinery. Screens copy Jobber's layouts using the CRM's existing components and CSS rules.

**Tech Stack:** Convex (dev deployment only), Next.js 16 App Router, TypeScript strict, Vitest + convex-test (`CRM/tests/`).

**Spec:** `CRM/docs/superpowers/specs/2026-11-18-finance-design.md`

## Global Constraints
- Amounts are whole cents; balances are computed from allocations, never typed.
- Dev deployment only; never `convex deploy` or `--prod` (root CLAUDE.md rule 2). The Convex CLI is not usable on this machine, so `convex/_generated/api.d.ts` gets each new module added by hand.
- File names under `convex/` use letters, digits, underscores, periods only (no hyphens).
- Every new Convex function starts with an access helper from `convex/crm/lib/access.ts` and validates its args.
- Additive only: the forms app, Jobber code, crons and existing tables are not edited (the single exception is widening `opportunities.pipeline` and existing quote deposits also writing a payment).
- UI rules (CRM/CLAUDE.md): skeleton for every waiting screen (`components/skeletons.tsx`, plus `loading.tsx`), hover and press feedback, fixed-width tables with `<colgroup>`, red-on-submit validation, motion on state changes, pagination (never infinite scroll), input filtering from `lib/fields.ts`, Jobber's green `#388523` the only accent.
- Roles: Admin and Office Team create/edit/send/record; Admin only: void, bad debt, delete draft, invoice settings; Sales and Project Managers read only.
- Tests: `cd CRM && npx vitest run`; typecheck `npx tsc --noEmit` in `CRM/` and in `convex/`; `npm run lint`; `npm run build` (unset `NODE_ENV` first).

## Review Focus
- A schedule that does not add to 100% or exceeds the total: rows must never overbill the project; the form shows what is left.
- A payment larger than an invoice's balance, or allocated to an invoice of another client or business: refused.
- Voiding or marking bad debt an invoice that has payments, and deleting a draft that a schedule row points at: the row must become available again.
- A project with no quote, no schedule or $0 total entering Finance: it must still be billable with a standalone invoice and must not stick or crash the board.
- Rounding: 3 equal rows of $100.00 (10,000 cents) split 33.33%/33.33%/33.34%; sums stay exact.
